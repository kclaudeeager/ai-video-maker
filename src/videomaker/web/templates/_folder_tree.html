{# Folder chrome: the cards you navigate by, the rows you land on, and the control that files a project. Context, via the macros: a `routes.projects.FolderNode` and the labels already in use. Four things are deliberate here. **Drill-down, not an open tree.** M3 shipped an always-expanded `
` tree, on the reasoning that you came back to find a project rather than to click your way to one. With ten projects that reasoning inverted: the page became a wall of identical cards you had to read end to end. A folder is now a card that links to its own page, so the root answers "where is it" in one glance and the folder page answers "which one". The tree is still built whole per request — it is derived from the rows and costs nothing — and each page renders one node of it. **Still no JavaScript.** A folder card is an `` and the move control is a `
` ending in a 303. Navigation is the browser's job; the M2 global constraint holds without a line of script. **Grotesque, and nothing warm — except the count that means a person.** A folder is chrome, so it is set in `--font-ui` in `--ink-soft` and borrows no colour. The one exception is the amber `waiting` badge, which means what amber means everywhere else in this UI: someone is waiting on you (`docs/ui-design.md` §3). A folder with nothing at a gate shows a plain count and no amber at all. **The move control stays a disclosure.** It is the rare action on a row that is mostly read, so it stays folded until asked for rather than sitting open as noise on every card — which is precisely how the flat list got heavy. #} {% macro move_form(project_id, current, folders, back) %} {# Free text, because typing a new label *is* how a folder is created — with a datalist so the tree does not sprout typo-siblings of what already exists. #}
